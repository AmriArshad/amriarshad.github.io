This year I built a multi-instance game server platform on a bare-metal Ubuntu machine at home for me and my friends. It hosts modded Minecraft and Terraria, with each Minecraft server isolated in its own container, and everyone connects without me opening a single port on my router.
<!-- more -->
---

## Why build it?

My friends and I wanted to play some modded Minecraft and Terraria, but we didn't want to pay for a hosted server or run it locally from someone's PC. If that person wants to close the game, the server closes with it. So the best solution was to build a self-hosted server.

## The stack

- **Ubuntu** on bare metal as the host
- **AMP** (Application Management Panel) to manage server lifecycle, backups and mod updates
- **Podman** containers so each modded Minecraft server is isolated from the others
- **playit.gg** tunnels to expose the servers to players

## Isolating servers with Podman

Every modded Minecraft server runs in its own Podman container. If one modpack needs something different from another, or one server misbehaves, it can't affect the rest. Podman is daemonless and can run containers rootless, which fits the goal of keeping the host as clean as possible.

This allows me to run multiple instances of several game servers with their own resource limits and configs without interfering with each other.

## Managing everything with AMP

AMP gives me a single panel for starting and stopping instances, scheduling backups and handling mod updates. That's the part that turns a pile of containers into a platform: the day-to-day operations are repeatable and I'm not SSHing in to restart things.

## Keeping the network closed

Rather than forwarding ports on my router, I use playit.gg tunnels. The tunnel agent makes an outbound connection, and players connect through playit.gg's address, so my home IP and network perimeter stay closed. It's the same idea as the Cloudflare Tunnel I used for n8n: let the service reach out instead of letting the internet reach in.

## What I learned

- **Isolation pays off.** Separate containers made it painless to run servers with different requirements on one host.
- **Management tooling matters.** AMP handling backups and updates is the difference between a hobby setup and something I can actually maintain.
- **Outbound tunnels beat open ports.** For a home network, avoiding port forwarding removes a whole class of exposure.
